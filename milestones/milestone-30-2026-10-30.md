## 4. Authority gate interface

```js
verifyIssuerAuthority(grant, { mode, exp29Evidence? | fixture? }) → Promise<result>
```

| Result | When | Authority classification |
| --- | --- | --- |
| `ISSUER_WAS_HISTORICAL_HOLDER_AT_SNAPSHOT` | `EXP29_FROZEN`, all checks pass | Experiment #29's `HISTORICAL / ARCHIVED_INDEXER_LOCATION / BITCOIN_CORROBORATED` |
| `FIXTURE_ISSUER_MATCH` | `TEST_KEY_FIXTURE`, all checks pass | `TEST_KEY_FIXTURE` |
| `DENY` + code | anything else | `null` |

Every result, positive or `DENY`, carries:

```text
current_ownership: false
build_permission_decided: false
operational_permission: false
```

**`ISSUER_WAS_HISTORICAL_HOLDER_AT_SNAPSHOT` was not reached and was not
simulated.** It is unreachable until a real signature exists (section 10).

## 5. Real-evidence and fixture mode separation

- **`EXP29_FROZEN`:** the gate runs Experiment #29's evaluator on the committed
  frozen evidence itself. The optional `exp29Evidence` can only replace raw
  evidence bytes, which Experiment #29 still checks against its pinned hashes.
  No holder, hash manifest or controller can be passed in.
- **`TEST_KEY_FIXTURE`:** a strict local fixture
  `{ source: "TEST_KEY_FIXTURE", district_inscription_id, authority_snapshot, holder }`.
  A fixture may not name the real historical holder, and it may not carry any
  other field (such as a real classification).
- Each mode accepts only its own inputs; mixing them returns
  `AMBIGUOUS_AUTHORITY_INPUT`.
- A fixture may reuse the real snapshot height and hash. Its result is still
  labelled `TEST_KEY_FIXTURE`, with all claim flags false.

Adversarial probes at the freeze preflight confirmed: forged transaction bytes
(`HASH_MISMATCH`), a smuggled holder entry (`UNEXPECTED_EVIDENCE`), override
options in real mode (`AMBIGUOUS_AUTHORITY_INPUT`) and a fixture carrying a real
classification (`INVALID_FIXTURE`) are all denied.

## 6. Canonical grant and BIP-322 signature verification

Checks, in order; any failure returns `DENY`:

1. Options: known mode and only that mode's inputs.
2. Canonical grant: `{ message, signature }` shape; Experiment #28 domain; two
   lines, no `\r`, no trailing newline; exact key set; bytes equal to
   Experiment #28 `grantMessage()`; schema; well-formed snapshot and grantor.
3. Scope: `937336.bitmap` and inscription `7b7c15dc…a9d1i0`.
4. Authority source: Experiment #29 `HISTORICAL_HOLDER` with its exact
   classification, or a valid fixture; its District and inscription must match.
5. Snapshot: grant height and block hash equal the authority snapshot.
6. Issuer: grantor address and script equal the authority holder.
7. Signature: `verifyBip322P2TR(grantor, exact grant bytes, signature)`.

The authority source is evaluated before the snapshot comparison so that
evidence failures are reported first. Both modes share these checks; only the
authority source and the labels differ.

## 9. Explicit limitations and trust boundaries

- **Real historical-holder authorization was NOT demonstrated.**
- **No real District-holder build-grant signature exists.**
- **Historical ownership is NOT current ownership.** A District transfer after
  972169 is invisible to this gate.
- **No operational build permission was granted.** Build validity (scope,
  expiry, revocation, builder) remains with Experiment #28, which is still
  `TEST_KEY_FIXTURE` / `LOCAL_ONLY`.
- **`TEST_KEY_FIXTURE` results are not real-world authority.** They describe
  deterministic test keys.
- **Experiment #29's trust limits are inherited**: the inscription location is
  an archived two-indexer observation with no raw indexer responses; Bitcoin
  facts are corroborated by two providers, not validated by a local full node;
  no sat-flow reconstruction.
- The real positive branch is untested by construction; its logic is exercised
  only through the shared fixture path.
- **No new signatures, wallets or economic transactions occurred.**

## 11. Future architecture note — unimplemented hypothesis

```text
2016_BLOCK_QUERY_EPOCH + ACTION_TIME_OWNERSHIP_PROOF
```

Preserved as a hypothesis only. **Nothing here is designed or implemented in
Milestone #30.**

- **Periodic query cache:** ownership lookups could be refreshed once per
  2,016-block epoch for discovery and display.
- **Action-time proof:** any consequential action would separately require fresh
  ownership evidence at the action height **and** BIP-322 proof that the signer
  controls that holder's key.
- The two must stay separate: a cached epoch result is never action-time evidence.
- **BIP-322 alone does not establish current District ownership.** A signature
  proves key control over specific bytes; ownership requires independent
  evidence of where the inscription is at the relevant height.

## 12. Final milestone verdict

**MILESTONE #30 — CLOSED / PASS / LOCAL / OFFLINE / FIXTURE-GATED / PUBLISHED EXPERIMENT**

An offline, deterministic gate binds a delegated build grant to the issuer's
authority at a specific Bitcoin snapshot. With real Experiment #29 evidence it
rejects every issuer except a correctly signing historical holder; that real
positive outcome remains unreached because no real holder signature exists.
The positive path is demonstrated only with `TEST_KEY_FIXTURE` keys. No current
ownership, operational permission or real-world authority is claimed.
